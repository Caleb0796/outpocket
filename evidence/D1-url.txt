So single-instance now holds by EXPLICIT CONFIGURATION (replica count 1,
requiring a deliberate edit plus Save to change) PLUS A STRUCTURAL GATE
(autoscale requires a workspace-plan upgrade nobody has bought) — a stronger
basis than the free tier's incidental single-instance-by-nature, which this
reason replaces.

WHY IT MATTERS AT ALL, kept from the first version because it is the
load-bearing part and does not change with the tier: S9's state digest lives
in one process's in-memory Map, and S6's TOCTOU closure and S12's sign lock
are all true by construction of a single process. A second instance
(intentional, or accidental via Render's own zero-downtime rolling deploy
briefly running two) would silently reintroduce all three — the digest would
diverge between instances and the lock races S6/S12 close would reopen.

WHAT WOULD MAKE THIS REASON STOP BEING TRUE — write the expiry down again,
the same discipline applied forward: a workspace-plan upgrade from Hobby to
one that supports autoscaling would un-gate the toggle. At that point
"cannot drift on silently" stops holding for the structural half of this
reason, and manual-scaling-at-1 alone (still an explicit, deliberately-set
value) would be what one-instance rests on until re-verified. Re-check this
file against the dashboard, not just the deploy's uptime, if the workspace
plan ever changes.
