## Iron rules you code against

Sole entry point `document.modelContext.registerTool(def, {signal})`;
`navigator.modelContext` removed in Chromium 150 — the installed major is **152**
(MEASURED), and what the alias does on 152 is node V0;
`provideContext` / `unregisterTool` / `clearContext` all gone. The browser does
**not** validate `inputSchema` — it parses JSON, checks for an Object, and calls
you. **Every write tool validates its own arguments in code.** Revocation does
**not** cancel an in-flight `execute` (Chrome 153+) — neither your code nor your
copy may claim it does. There is **no binary channel**: agents cannot deliver
images or PDFs; the receipt tool may only link an existing id. Annotations are
exactly `readOnlyHint` and `untrustedContentHint`; `outputSchema` does not exist.
Never encode workflow order in a description — the registration state machine is
the workflow. The ≤500-character description and ≤1500-character output budgets
are **PUBLISHED official guidance, not enforcement**: grade them PUBLISHED, never
MEASURED. Measured cost: registration ≈37 µs/tool, revocation ≈1.1 µs/tool —
cheap; do not optimise it. A surface flip costs ≈1.25× prompt-cache write;
**never claim it saves tokens.**

## Output format

The state names are the canonical ones, and the counts are what
`countinghouse/src/tools.js:343-354` actually produces:

```
NODE:     T3
FILES:    <paths>
STATES:   signed-out 1 | employee-no-report 5 | draft-dirty 12 | draft-clean 13 |
          submitted 6 | auditor 6    (asserted, SET EQUALITY on names)
ACCEPT:   <command> -> PASS
PIT:      kb/pits/T3.md
```

Note what that table says and the old one hid: **13 is the clean draft** (12 plus
`submit_expense_report`, added only when the report is clean and has lines), 12 is
the dirty draft, and once a report is no longer a draft the surface **shrinks to
6**. It does not grow after signing. A template that names the states wrong
produces flip assertions that are right by accident or wrong quietly.
