# Pit — V5 (throwaway HTTPS probe origin)

**TRIED.** Two things, one per session. (a) Carry V5 as done because its visible
artifacts were done: the origin was live, `evidence/V5-origin.txt` and
`evidence/V5-headers.txt` were captured, the page was deployed and serving.
HANDOVER and `evidence/UNKNOWNS.md` both recorded the node as complete. (b) Then,
on re-dispatch, write one schema that covers every V-lane evidence file on disk —
`evidence/V1.json`, `evidence/V1-remote.json`, the block `probe/index.html`
renders, and `evidence/V0.json`.

**HAPPENED.** (a) `erp/contracts/probe-verdict.schema.json` had never been
written. It is a declared `V5` output and it is the file `V1.accept` ajv-compiles
on Day 1, so V1 could not have started. Nothing caught it because nothing diffed
the node's `outputs` list against disk — four of five outputs existed, and four of
five is indistinguishable from done if you only look at what is there. It is also
the ninth file `S10` freezes and sha256-hashes on Day 1, and the hard edges
`V5 -> S10` and `V5 -> G6` exist precisely to order that; the edges were right and
the artifact was missing anyway.

(b) `evidence/V0.json` cannot validate against a probe-verdict schema, and should
not. `V0.accept` declares a different shape on purpose — `{chromeMajor, flag,
headless, navigatorAlias, documentPresent, toolCount, cdpDomainEnabled,
invokeToolRoundTrip, method:'cdp'}`, in its own words *"the same shape as
`evidence/H2-reachability.json` on purpose: one evidence format, one set of traps,
two nodes."* One format is a human reading a built-in browser that CDP cannot
drive; the other is a script driving Chrome over CDP. A schema loose enough to
accept both would have to drop `origin`, `chatgptModel`, `modelContextPresent` and
`toolCount` from `required` — every content field `V1`'s gate exists to check —
and would then pass `{}`.

(c) A third, quieter one, found while writing the schema: under the ajv
construction `V1.accept` specifies — `new Ajv({strict:false})`, `ajv/dist/2020`,
no `ajv-formats` — the `format` keyword is **inert**. An unknown format is
downgraded to a warning and validates nothing. A `format:"date-time"` on
`observedAt` would have looked like a constraint and been decoration.

**CHANGED.** Wrote the schema with the five fields `V1.accept` names, and put the
scope boundary in the schema's own `description` so the V0 question is answered
where it will next be asked. `pattern` carries every constraint `format` appears
to; `provenance.schema.json` already pairs the two for the same reason and emits
the identical warning today, so this is house behaviour and not new noise.
`toolCount` is `minimum: 0` and deliberately not pinned to 5 — `modelContextPresent:false,
toolCount:0` is the negative V1 outcome PM must hear about the same day, and a
schema demanding 5 would make the finding that matters most unrecordable.
`additionalProperties` stays open because `evidence/V1-remote.json` already
carries field notes and closing the object would fail a human-gated node over
prose. Verification was done by rendering the live page with Playwright and
reading `#verdict`'s actual `textContent` — both the WebMCP-present and
WebMCP-absent branches, locally and against `https://webmcp-probe.onrender.com` —
rather than by reading the shape off the source.

**EARLIER.** Diff a node's `outputs` list against disk before calling it done.
Visible artifacts are not the output list, and the missing one is by definition
the one you cannot see. This is graph-wide, not a V5 quirk, and it is live right
now one node over: `V0` has the same defect. `evidence/V0.json` on disk matches
neither `V0.accept`'s shape nor the probe-verdict shape — it has `chromiumMajor`
where the accept says `chromeMajor`, `method:"page-side feature detection…"` where
the accept says `'cdp'`, and no `flag`, `headless`, `toolCount`, `cdpDomainEnabled`
or `invokeToolRoundTrip` — and its second declared output `harness/probe-v0.mjs`
does not exist. Second, smaller: when a schema is asked to cover two evidence
files, check whether the graph already declares them as two shapes before
widening anything.

Also recorded because it will otherwise surprise someone: the page deployed at
`https://webmcp-probe.onrender.com` is **not** byte-identical to `probe/index.html`
— 22 diff lines, all cosmetic de-branding (`<title>`, the subtitle, one `<h2>`,
and two comments that named `FACTS.md IR-16` and the schema path). Every tool
registration and the whole `render()` verdict construction are identical, so there
is no behavioural difference, but "the deployed page" and "the repo page" are two
artifacts and anything that hashes one must not claim the other.

**GRADE.** MEASURED. `V5.accept` re-run verbatim from `erp/graph.json` on
2026-08-29 against the warm remote origin: `HTTP/2 200`, `Origin-Agent-Cluster`
absent, OAC check exit 0. `GET /whoami` discriminates on the remote origin
(`cookiePresent:false` bare, `cookiePresent:true, cookieMatches:true` with the
cookie the page sets). Five tools at load confirmed from the live render, not from
source. `V1.accept`'s ajv command run verbatim over `evidence/V1.json` exits 0.
