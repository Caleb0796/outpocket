# Pit — E2

*C4's five fields, delivered in its COMMIT under clause 6e. L1 transcribed, did not compose.*

**TRIED.** Encoded the six canonical capability states, made the evaluator **load expected
tool-name sets from the exported artifact AT RUNTIME**, and required exact SET equality.

**HAPPENED.** The implementation was complete, but **my own Chrome launch and commit were
blocked by sandbox boundaries**; the real-Chrome acceptance run later matched all six states
with none skipped.

**CHANGED.** The capability suite definition, the surface expectations, and the evaluator logic
that performs the runtime exact-set checks.

**EARLIER.** **Take expected sets from the runtime export; transcribing
`surfaces.expected.json` would only check my copy against my copy.** Also watch the naming
crossover: **exported `S2-emp-draft-clean` is the compiler-internal `S3`.** That crossover did
cost me investigation time before I reconciled the two naming schemes.

**GRADE.** Accept when all six canonical states match exported tool names by set equality, with
zero skipped; **do not grade the signature path and do not accept count equality.**

---

**Why set equality rather than count (L1's note, from the frozen contract).** `S4-emp-submitted`
and `S5-aud` carry the SAME NUMBER of tools and are NOT the same set. **A count assertion
passes even if the auditor is handed the employee's surface** — the single worst thing this
product could do, and the exact claim the demo makes. The predicate says "never by count
equality" in its own text, and that clause is the node.

**The crossover has now cost four documents and a seat's investigation time.** It is why D-99
bans naming a draft state without its namespace: write "internal S2 (the dirty draft)" or
"export S3-emp-draft-dirty", never a bare S2.

**Verified by L1, not by the gate.** My merge gate refused this node on span 0 exit 2 — `$URL`
is unbound in the gate's environment and nothing boots a server for it, the same gap that
refused H4 and D1. Bound to a locally booted server the accept reads: *"capability: 6 of 6
canonical states matched; zero states skipped; expected sets taken from
artifacts/tools.export.json at runtime; set equality on tool names, never by count equality."*
**The gate's red was my environment, not the node** — and a gate that cannot supply a
predicate's inputs is a gap worth naming rather than working around silently.
