# Pit — H4

*Reported by I1 in its own words at the merge gate (D-74/D-31); L1 transcribed, did not compose.*

**TRIED.** Read the predicate as an adversary before writing anything, because it is the weak
kind: two runs at the SAME seed, compared with `diff`, **which two empty files pass**. So I
built the falsifiability in rather than bolting it on. The demo is **SEEDED rather than
scripted** — a hard-coded script is also deterministic and would have made the accept pass
while proving nothing, since nothing ever varies. Seeding splits it into two separately
falsifiable claims: **the dump is stable, AND the dump observes something.** Only the second
catches a broken dump. `dump-state.mjs` then refuses to emit an empty dump at all, which
converts the cheapest way to pass into a loud failure.

**HAPPENED.** The first run exited 0 and I nearly had a green node. It reported all seven demo
steps `ok`, and it had created NO report — coverage showed `reports:1`, which was the
pre-seeded archive, and `openReportId:null`. **I only caught it because "reached S1" was
printed on stderr and S1 is not S3. THE `ok` FLAGS WERE LIES:** `compile.js`'s `toolset.call`
NEVER THROWS for the two failures that matter — an unknown tool comes back as a normal content
block reading `No tool named "x"`, and a refused action comes back as `Error [CODE]:` through
the error envelope — so a try/catch reports success for a demo that did nothing at all. That is
a derived boolean disagreeing with the raw text it came from, and it is the same shape as V2's
and the same shape as the banner. Underneath it were two real bugs: `create_expense_report`
needs `project` and I had passed only `title` (`PROJECT_SCOPE`, 403), and once fixed, the
amounts tripped `RECEIPT_REQUIRED_AT` and parked the demo at S2. Receipts are attached by the
HUMAN in the page; no tool can attach one, so the demo must stay under that cap rather than
pretend.

**CHANGED.** `src/page/demo-mode.js` and `harness/dump-state.mjs` new, `harness/drive.mjs` grew
`--dump-state`. Nothing in `erp/graph.json` or `erp/PATHS.md`, and `index.html` untouched.
Three things are DERIVED rather than typed, all for the same reason — a constant that moves
must not silently stop producing the intended state: the project comes from
`get_session_scope`'s own answer with CLOSED entries skipped; the amount ceiling is
`LIMITS.RECEIPT_REQUIRED_AT - 1` imported from `src/policy.js`; and the step grading reads the
surface via `tools.names()` instead of trusting a returned promise. The demo signs in through
the page's own `[data-persona]` affordance because sign-in is a human act no tool can perform,
and **it deliberately does NOT submit: signing is the human's act and a demo that faked it
would lie about the one property this project exists to demonstrate.**

**EARLIER.** What I would tell myself is: **THE STDERR LINE THAT SAVED ME WAS AN ACCIDENT, SO
STOP RELYING ON ACCIDENTS.** I printed "reached S1" only because it seemed useful for
debugging, and it is the single reason I did not ship a green H4 with an empty filing in it.
The predicate said 0, the steps said 7/7 green, and one incidental log line said S1 — **the log
line was the only honest witness in the room.** The rule I should have started from is the one
I now believe is the real content of the house rule: **WHEN A CHECK REPORTS SUCCESS, ASK WHAT
IT WOULD HAVE PRINTED HAD IT FAILED, and if the answer is "the same thing", the check is not a
check.** My `ok` flag would have printed `ok:true` for every possible failure, which I could
have known by reading `toolset.call` — twenty lines, and I had already read them for H3. And
more specifically: I keep finding that in this codebase **the ERROR PATH RETURNS NORMALLY.**
The tool surface is deliberately built that way, so an agent gets a readable sentence instead
of a rejection. That is right for agents and it is a trap for harnesses, and I have now been
caught by it once. Anything I write that consumes a tool result must grade the TEXT, never the
absence of a throw.

**GRADE.** MEASURED. Accept green through `accept-gate --run-clean 0` with both runs reaching
S3; seed 7 vs seed 8 differing in title, line count, merchants, dates and amounts; four
distinct refusal paths each producing zero bytes; coverage read out of the dump itself rather
than inferred. NOT measured: nothing here has run in the ChatGPT built-in browser, and **the
dump has never been taken across an actual midnight** — the relativisation is reasoned and
unit-consistent but the 00:00 case is argued, not observed.
