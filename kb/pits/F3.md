**EARLIER — I NEARLY SHIPPED MY STRONGEST-LOOKING ASSERTION AS MY EMPTIEST ONE.**
"`canonicalDigest` is unchanged" LOOKS like the most rigorous form of "it did not mutate" — it
covers the whole projection, it is one line, it reads as thorough — **and that appearance is
exactly what makes it dangerous, because its rigour is entirely contingent on a fact about the
projection that the assertion itself does not check.**

So I probed it. The first probe reported `digest changes on a real mutation: false`, which read
like my strongest assertion was vacuous. It was not: **I had tested sensitivity with an AMOUNT
change, and the fixture's `usdCents` is null (no FX rate in that context), so the amount was
never in the digest to begin with.** I measured a mutation OTHER than the one under test and drew
a conclusion about the one under test.

Measured correctly: attaching a receipt does NOT move the digest (it is not on a line yet), and
linking one DOES. That is now committed as test 5.

**The generalisable rule: an assertion that something did NOT change is only as strong as your
evidence that it COULD have — and that evidence has to come from the same mutation the test is
about.** The failure mode is not "forgot to check", it is **"checked badly and believed the
result"**. For every did-not-change assertion, commit the did-change control beside it, using the
operation under test.

**GRADE.** GREEN, and verified in the one direction that mattered rather than only in the
direction that passes.

**Two notes from the same probe, neither actionable by UX.** `erp.canonicalDigest("RP-9999")`
THROWS `ErpError NOT_FOUND` rather than returning null — fine, but anything computing digests
over a list of ids needs to know. And `usdCents` is null for a line created with amount "12.00"
in a bare `createErp()` fixture, presumably because the FX table binds elsewhere; harmless here,
but a downstream node asserting on `usdCents` from a bare fixture will get null and read it as a
test bug for an hour.
