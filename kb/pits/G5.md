# Pit — G5

**TRIED.** Built the ownership pre-commit hook against two FIXTURE invocations rather than an
ambient `git diff`, which is what `G5.accept` and `erp/charters/L1.md` both require. The hook
resolves the seat from the branch name (`seat/<SEAT>-<NODE>`), exits 0 with a message on any
non-seat branch including `main`, and grades the STAGED set — the diff the commit is actually
about — rather than the working tree. It reuses `tools/check-ownership.mjs` (G0) instead of
reimplementing `conventions.ownership_rule`, because the graph says that file implements the
rule "and nothing else".

**HAPPENED.** All three clauses green: the ok fixture exits 0, the bad fixture exits 1 naming
`server/index.mjs`, and `git config core.hooksPath` prints `.githooks`. The bad fixture is a
better test than it looks — `server/index.mjs` is denied for I2 under clause (a), as a declared
output of S1 whose owner is I3, not merely by a glob.

**AND THE HOOK DOES NOT FIRE. THIS NODE'S ACCEPT PASSES AND ITS PRODUCT IS INERT.** I staged a
path L1 may not write, committed, and the commit SUCCEEDED. The cause is not a bug in the script:
**git only ever invokes a hook named `pre-commit`.** There is no `pre-commit-ownership` hook in
git. `.githooks/pre-commit` exists and is G4's — it runs the Layer-0 lint, passed, and let the
commit through. `core.hooksPath` being `.githooks` registers the DIRECTORY; it does not make git
run every file in it. So "registered", as this accept defines it, does not imply "invoked", and
the node ships a script nothing calls until `.githooks/pre-commit` chains to it. That file is
I4's and I did not touch it. Filed for PM, and requested of I4 as a one-line chain.

**THIS IS THE THIRD INSTANCE OF ONE CLASS IN ONE DAY, AND THAT IS THE FINDING.** Exit 0 is also
satisfied by a check that discovered nothing. (1) `L0` gate (7) already refused `npm test` exit 0
in favour of "24 tests, exactly 1 failure, and that failure named" — the graph had this right
before the sprint started. (2) `T1`'s second clause passed with **0 of 0** registerTool call
sites: the invariant is asserted on Day 1 when it cannot fail, the call sites arrive with T2 on
Day 2, and no accept in the graph re-runs `tools/check-toplevel.mjs` — found by the peer session
`mcp-6d`, which searched every accept before saying so. (3) This node. **A predicate that cannot
distinguish "passed" from "had nothing to look at" is not a gate.** PM's D-36 prices the second
occurrence of a defect class as a missing instrument; this class reached three in a day.

**CHANGED.** Nothing in `erp/graph.json`. The probe commit that proved the hook inert was reset
out of the branch; it was a deliberate experiment and it is not in the history.

**EARLIER.** Two, and both are the same error twice in ten minutes: acting on a check I had not

dispatch prompt now says so.**
