# Pit — V2

Reported by **I1** under D-31, in its own words, transcribed by L1.

**TRIED.** Read the merged evidence first, as dispatched, and the answer was already partly there
— but so was the reason the node was still open. `graph.json` R-43 grades the existing
`evidence/V2.json` itself: a *manual reading*, "decisive enough to steer the design and not
sufficient to close their nodes," and it names exactly what was missing — "V2 wants a before/after
count pair and a wall-clock gap." It had one after-count, no before-count, no gap,
`origin: http://localhost:8795`, `chromiumMajor: 151`. So the job was to supply the pair. V2 is
**not** in `graph.json.human_gated` (only G1, V1, D4, D5, D6 are) and the accept never names the
built-in browser — it asks for tool-count observations — so I measured over CDP on the installed
Chrome 152 against the **remote** origin, per the charter rule that a green localhost run is not
evidence. The rig was written throwaway in the job tmp dir, not the repo: V2's only declared
output is `evidence/V2.json` and `harness/**` was out of scope. Its sha256 and full CDP step list
are recorded inside the evidence so the pair stays auditable without it.

**HAPPENED.** Green, 8/8, and the run found something the localhost reading could not. The
surface goes 5 → 6 on one un-reloaded document, and Chrome 152 **pushes** `WebMCP.toolsAdded`
naming `probe_extra` 1 ms after the invoke — unprompted, no poll. **So the next-turn behaviour the
built-in browser showed is a CLIENT POLICY, not a browser limitation** — the same shape as
`V6-consent-gate` — and it closes nothing: a different client or a future version may differ.
Verdict stays `refreshes`, no document is contradicted.

Second, smaller finding: `toolsAdded` fires **one event per `registerTool` call** (six events, one
tool each), where H2's single-tool fixture could only ever show one event carrying a one-element
array. Neither channel contradicts the other.

The accept's single backticked span is the bare word `verdict` — a field name — so
`accept-gate --run-clean 0` exits 127 with the runner's own "this is the SHELL rejecting it, NOT
the node failing" banner. I graded the clause by the means it describes, with the accept string
and its enum read out of the authority at runtime rather than retyped.

**CHANGED.** Nothing in `erp/graph.json` or `erp/PATHS.md`, in either direction. One file written,
my declared output; the ownership hook confirms `[declared output of V2 (owner I1)]`, 0
violations. **The prior manual reading was PRESERVED, not overwritten**, under
`builtInBrowserReading` with its localhost/Chromium-151 provenance intact, and the fact that it
has never been re-run on the remote origin is recorded as an open item rather than quietly closed.

**EARLIER.** The first run reported `probeExtraPushed: false`, and I was one step from publishing
"Chrome 152 does not push tool-surface changes to an attached client" — **which is false.** It was
**my** defect: I captured the event-array index *after* `await responded`, so the `toolsAdded`
that arrived 1 ms into the invoke was already in the array before my slice began. The raw event
list caught it — `{"atMs":1788035591166,"names":["probe_extra"]}` was sitting in the output I was
about to summarise away. That is `kb/pits/L0.md` lesson (b) in a second costume, and the
generalisable form is worth carrying to whoever writes the next probe: **when a derived boolean
disagrees with the events it was derived from, suspect the derivation — and slice an event buffer
from an index captured BEFORE the trigger, never after the await.**

That first run's 4048 ms gap was pure rig artifact (a bounded wait loop spinning out) and is
explicitly **not** reported as the gap; it is flagged in the file so nobody reconciles two numbers
later. Fixed, re-ran twice; runs 2 and 3 agree exactly, and run 3 is recorded as
`confirmingRerun`, clearly marked **not** the graded pair, because one run of a rig that had
already been wrong once is not worth much.

`FORCE_COLOR=3` is live in this seat (confirmed by `env | grep -i color`); the checker writes
plain strings only and never greps a colourising tool's output, so lesson (a) did not bite.

**GRADE.** MEASURED — at the browser layer, on the remote origin, on the installed Chrome 152,
with no agent connected. The client layer stays a manual reading and is labelled as one.
