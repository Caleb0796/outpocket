**EARLIER.** Two things, one a false alarm and one live.

The false alarm, which the re-dispatch itself named: a peer session grepped
this branch for `localeCompare` and nearly filed it as a violation. Re-running
that grep now, every hit inside `src/canonical.js` is the one-line comment
stating the ban (`// ... never localeCompare, which is ICU-dependent...`), and
every other hit across the repo (`erp/CONTRACTS.md`, `erp/graph.json`,
`erp/charters/I3.md`, etc.) is documentation of the same ban. `git grep` does
not distinguish "this string appears" from "this string is live code doing the
banned thing" — a grep hit is a lead, not a finding, and confirming it means
reading the line, not counting the match. Same shape as [[L0]]'s FORCE_COLOR
case: an observation confirmed by the tool still needs the right explanation
underneath it before it becomes a claim.

The live one, and this is NOT inside `src/canonical.js` or any file S11
outputs, so it is out of scope to fix here but wrong to sit on: `src/erp.js:385-387`
has a second, real canonicaliser — `canonicalDigest()`, feeding
`fnv1a(JSON.stringify(...))` over a `lines` projection, sorting itemization by
`.label.localeCompare(b.label)` and the line array by
`(merchant+date).localeCompare(...)`. That is exactly the shape the charter
says is deleted ("a second, incompatible definition... It is deleted") and
exactly the FNV-1a-over-a-narrowed-projection bug
`erp/contracts/canonical-vectors.json`'s own note describes as the reason v6/v7
exist. It is not S11's output and I have not touched it, but whichever of my
own later nodes (or another node entirely) owns `src/erp.js` needs to know
this function is still live before claiming "the only canonicaliser in the
project" for the whole tree, not just for the digest path OCF-1 replaced.
Flagging it here rather than fixing it, because this dispatch was one job and
a silent drive-by edit under a "write the pit" re-dispatch would be exactly
the kind of scope creep the pit format exists to make visible instead of
hidden.
